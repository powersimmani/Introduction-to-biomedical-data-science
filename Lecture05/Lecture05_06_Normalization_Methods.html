Normalization Methods in RNA-Seq Analysis
RPKM/FPKM Issues
Reads/Fragments Per Kilobase Million - biased by composition
TPM Calculation
Transcripts Per Million - better for comparison
DESeq2 Normalization
Median-of-ratios method for differential expression
TMM Method
Trimmed Mean of M-values - robust to outliers
Batch Correction
ComBat, limma removeBatchEffect for technical variation
💡 Choose normalization method based on your downstream analysis goals
Decision Tree: Choosing the Right Normalization Method
What is your analysis goal?
📊 Visualization / Comparison
Compare across samples?
✓ YES → Use TPM
✓ NO (within-sample) → TPM or RPKM acceptable
🧬 Differential Expression
Have raw counts + replicates?
✓ YES → Use DESeq2 or TMM/edgeR
✗ NO → Not recommended for DE
🔬 Batch Effects / Technical Variation
Batch labels known?
✓ YES → Use ComBat or limma
✓ NO/Unknown → Use SVA or RUVSeq
💡 Important Decision Guidelines
  • NEVER use RPKM/FPKM for differential expression - composition bias will produce false results
  • Always normalize before batch correction - normalize first, then correct for batch effects
  • Validate your choices with PCA plots - visualize data before and after normalization/correction
  • Consider experimental design - blocking in the model can be better than pre-correction
Common Mistakes to Avoid
1
Using RPKM/FPKM for Differential Expression Analysis
❌ Wrong Approach:
# Calculate RPKM for all samples
rpkm_values <- calculate_rpkm(counts, gene_lengths)
# Compare RPKM between conditions
t.test(rpkm_treatment, rpkm_control) # ❌ WRONG!
✓ Correct Approach:
# Use DESeq2 with raw counts
dds <- DESeqDataSetFromMatrix(countData = counts, ...)
dds <- DESeq(dds)
results <- results(dds) # ✓ CORRECT!
Why it's wrong: RPKM/FPKM suffer from composition bias. If a few genes are highly expressed in one condition, they artificially lower the RPKM values of other genes, creating false positives and negatives.
2
Normalizing Already Normalized Data
❌ Wrong Approach:
# Download TPM data from GEO
tpm_data <- read.table("GSE12345_TPM.txt")
# Apply DESeq2 to TPM ❌ WRONG!
dds <- DESeqDataSetFromMatrix(tpm_data, ...)
✓ Correct Approach:
# Always check if data is already normalized
# If TPM/FPKM: use as-is for visualization
# For DE: get raw counts or use limma-voom
Why it's wrong: Normalization methods expect raw count data. Applying normalization to already normalized data distorts statistical properties and invalidates downstream analysis.
3
Batch Correction Without Validation
❌ Wrong Approach:
corrected_data <- ComBat(data, batch)
# Proceed without checking ❌ WRONG!
✓ Correct Approach:
# BEFORE correction: plot PCA
pca_before <- prcomp(t(data))
# Apply correction
corrected <- ComBat(data, batch)
# AFTER correction: validate with PCA!
pca_after <- prcomp(t(corrected))
Why it's wrong: Batch correction can accidentally remove biological signal. Always visualize before and after with PCA plots.
4
Filtering After Normalization
❌ Wrong Approach:
dds <- DESeq(dds) # Normalize first
filtered <- dds[rowMeans(counts(dds)) > 10, ] # ❌ WRONG!
✓ Correct Approach:
# Filter BEFORE normalization
keep <- rowSums(counts(dds) >= 10) >= 3
dds <- dds[keep, ]
dds <- DESeq(dds) # Then normalize ✓
Why it's wrong: Low-count genes affect normalization factor calculation. Filter lowly expressed genes BEFORE normalization.
5
Comparing TPM Across Different Experiments
❌ Wrong Assumption:
"TPM values sum to 1 million, so I can directly compare Gene X's TPM from Study A (TPM=500) with Study B (TPM=500)" ❌ WRONG!
✓ Correct Understanding:
TPM values are relative within a sample. Different studies may have different gene annotations, protocols, or RNA composition. Use reference genes or batch integration methods for cross-study comparisons.
Why it's wrong: While TPM is better than RPKM for within-study comparisons, it's not universally comparable across different experiments without additional normalization.
🎯 Key Takeaways
1. Data Type Matters
Always use raw counts for DE analysis
2. Order Matters
Filter → Normalize → Batch Correct → Analyze
3. Always Validate
Use PCA plots before and after corrections
4. Context Matters
Choose normalization based on analysis goal
📊 Quick Selection Guide
For Visualization & Comparison:
Use TPM - consistent totals enable direct comparison between samples
For Differential Expression:
Use DESeq2 or TMM/edgeR - statistical models for count data
Avoid for DE Analysis:
RPKM/FPKM - composition bias makes them unsuitable for statistical testing
For Multi-Batch Experiments:
Apply batch correction after normalization, validate with PCA
